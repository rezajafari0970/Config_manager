# اصلاح صفر بودن تشخیص رزیدنتال — P61

وضعیت: **اصلاح تشخیص نصب و نتیجهٔ مثبت واقعی مشاهده شد؛ بررسی پایداری خروجی هنوز کامل نیست.**

نسخهٔ معیار `ads-egress.v7`، پایگاه داده schema34، انتشار `p61c-07c512309847e2633957`.
کد اجرایی آزموده‌شده: `d37f5b64bbfe11c34c58ca0310e598e1e5e56c06`.
شش برنامهٔ بازسازی‌شده از شاخهٔ اصلی با فایل‌های در حال اجرا تطبیق کامل داشتند.

## علت صفر بودن

1. معیار قبلی شاهد IP مبدأ تلگرام و اینستاگرام را اجباری کرده بود، در حالی که درایور آن‌ها فقط دسترسی HTTPS را مشاهده می‌کرد. نبود شاهد تولیدنشدنی باعث UNKNOWN می‌شد. اکنون این دو مقصد کنترل تکمیلی‌اند و نبود مشاهدهٔ مسیرشان صریحاً ثبت می‌شود.
2. کنترل باید با خانوادهٔ IP همهٔ دامنه‌های Ads هم‌زمان یکسان می‌بود؛ ترکیب IPv4 و IPv6 شرط را ناممکن می‌کرد. مقایسه اکنون برای هر مقصد، در همان نوبت و خانوادهٔ IP انجام می‌شود.
3. نوبت جبرانی فقط مقصدهای ناقص را تکرار می‌کرد و کنترل هم‌زمان نداشت. اکنون موج کامل مقصدهای الزامی تکرار می‌شود.
4. دریافت بدنهٔ بزرگ اینستاگرام خطای سقف حجم می‌ساخت؛ مشاهدهٔ دسترسی اکنون از HEAD استفاده می‌کند.

## معیار و محدودهٔ اثبات

هر شش مقصد Ads در خام و قالب باید شاهد معتبر داشته باشند. هر مقصد در حداقل دو نوبت به شاهدهای پایدار هم‌خانواده و همان نوبت، از دست‌کم دو گروه مستقل شامل گوگل عادی، نیاز دارد. کنترل‌های دارای امکان مشاهدهٔ IP مبدأ: گوگل عادی، Cloudflare و ipify. هم‌پوشانی معتبر هر کنترل با Ads، حتی کنترل تکمیلی، مانع انتشار است. timeout و خطای HTTP اثبات بلاک نیستند.

برچسب محصول به معنی **جدایی تکرارشوندهٔ مسیر Ads در محدودهٔ مشاهده** است. این شواهد همهٔ ترافیک اپ‌ها، مسیر مشاهده‌نشدهٔ تلگرام/اینستاگرام، QUIC یا نوع ISP خانگی را اثبات نمی‌کنند. `evidence_profile=ads-stable-controls.v1` ثبت می‌شود و هنگام نبود پوشش کامل منبع، `coverage_complete=false` باقی می‌ماند. IP عمومی کنترل به جریان Ads نسبت داده نمی‌شود. کنترل چرخشی یا شاهد ناقص همچنان UNKNOWN است.

## نتیجهٔ واقعی

- آزمایش خصوصی نهایی روی کد تشخیص: ۷ ورودی، ۳ مثبت و ۴ منفی در ۵۰٫۲۲۷ ثانیه؛ هر چهار قالب خروجی کنترل شد. نمونه‌ها هدفمند بودند و نرخ موفقیت کل مخزن نیستند.
- در بررسی منسجم تولید پس از اصلاح تشخیص، ۱۱ هویت یکتا در JSON، JSONL و خام و یک کانفیگ در خروجی چرخشی تأیید شد. چهار پاسخ نسل یکسان، SHA256 صحیح و محافظ ایران داشتند؛ هویت تکراری مشاهده نشد.
- بازبینی خودکار همان هویت پذیرفته‌شده نیز مشاهده شد و پس از تمدید در خروجی باقی ماند.
- در آزمون فشار آخرین انتشار، شمارش API بین ۱۲ و ۱۳ عضو قابل انتشار بود. این آزمون موفق نبود: یکی از درخواست‌های next.json پس از حدود ۳۰ ثانیه به مهلت رسید. شمارش این بازه جای تأیید منسجم نهایی چهار خروجی را نمی‌گیرد.
- پس از این آزمون، یک بازیابی watchdog مشاهده شد. هنگام ادامهٔ بررسی، اتصال ابزار مدیریت به دستگاه serverprojects.ptr.network قطع شد. آفلاین بودن ابزار به‌تنهایی وضعیت روشن/خاموش بودن سرور را مشخص نمی‌کند.

## اصلاحات عملکرد و مشکل باقی‌مانده

پاک‌سازی مخزن هنگام انتظار برای اتصال نویسنده، قفل فایل‌ها را نگه می‌داشت. مهلت مستقل ۲۵۰ میلی‌ثانیه برای بررسی هر مرجع اضافه شد؛ timeout یا پاسخ دیررس اجازهٔ حذف نمی‌دهد. قفل پین‌ها، بررسی مرجع فعلی و چرخهٔ بعدی پاک‌سازی حفظ شدند. آزمون بازتولید روی کد قبلی شکست خورد و با اصلاح عبور کرد.

این اصلاح به‌تنهایی کافی نبود: آزمون فشار نسخهٔ میانی در ۷۸٫۷۱۵ ثانیه شکست خورد. سپس پرس‌وجوی صف بیکار به خواندن WAL منتقل شد؛ تمام پذیرش‌ها و پاک‌سازی محدوده همچنان پس از گرفتن اتصال نویسنده دوباره بررسی می‌شوند. نتیجهٔ بررسی اولیه کش نمی‌شود. آزمون‌های صف خالی، نتیجهٔ منفی کش‌شده، کار آینده، حالت غیرفعال، اجارهٔ فعال و تغییر محدوده هنگام انتظار موفق شدند.

با این وجود، آزمون فشار نسخهٔ نهایی در ۵۸٫۶۵۲ ثانیه با timeout خروجی چرخشی شکست خورد. اندازه‌گیری مستقل SQL انتخاب خروجی چرخشی روی اتصال تازه حدود ۰٫۰۳۲ ثانیه بود؛ بنابراین کندی را نمی‌توان صرفاً به آن SELECT نسبت داد. نمونه‌برداری مستقیم پردازنده فعالیت و رقابت فراوان در مسیر ClaimEgressLane/SQLite را نشان داد. هزینهٔ پرس‌وجوهای صف زیر هم‌زمانی هنوز باید بررسی و اصلاح شود. watchdog افزایش یا غیرفعال نشده است. **پایداری کامل یا رفع همهٔ مشکلات ادعا نمی‌شود.**

## آزمون و حفظ داده

دور کامل نهایی race/vet/ساخت/قالب‌بندی/ماژول‌ها و تست‌های Python و JavaScript با کد خروج صفر در ۱۰۴۹٫۰۰۲ ثانیه پایان یافت؛ آزمون کامل پنل ۱۰۳۵٫۶۴۴ ثانیه بود. آزمون بازیابی پردازشگر، watchdog مستقل و مرورگر در عرض‌های ۳۹۰ و ۱۴۴۰ پیکسل موفق بودند. موفقیت این آزمون‌ها جای موفقیت آزمون فشار زنده را نمی‌گیرد.

اجرای نسخه روی کپی داده، تمام ۴۲۹۹۴ ردیف کار و دیگر شواهد، تنظیمات و آمار را بدون تغییر نگه داشت و بازگشایی مجدد نیز بدون تغییر بود. هنگام نصب آخرین نسخه، ۲۱۹۳ نتیجهٔ منفی/پشتیبانی‌نشده حفظ شد؛ ریست تازه‌ای انجام نشد. توقف تا آمادگی پنل ۱۱٫۱۱۳ ثانیه بود. نسخهٔ پشتیبان هماهنگ در حالت توقف سرویس‌ها نگه‌داری شد و شش سرویس/فایل اجرایی کنترل شدند.

صف هویت یکتا، کش نتایج کامل‌شده، بازبینی ایمنی پذیرفته‌شده‌ها، محافظ چسبندهٔ ایران، TLS معتبر و اتصال شواهد به خام/قالب/هسته حفظ شدند. هیچ دکمهٔ شروع پردازش اضافه نشد.

## بازبینی API و سرعت

بازبینی متمرکز API با `gpt-6-astra` و `reasoning.effort=max` وضعیت completed داشت؛ ایراد محاسبهٔ پوشش شواهد پیدا و اصلاح شد. درخواست اولیهٔ حالت pro به سقف خروجی رسید و incomplete بود. هیچ کلید یا کانفیگ واقعیِ دارای اطلاعات اتصال برای مدل ارسال نشد و وابستگی API به اجرای دائمی اضافه نشد.

آخرین اندازه‌گیری هزار هویت از گروه اولیهٔ P60 برابر ۸۱۲٫۰۱۱ ثانیه بود؛ هدف ۶۰۰ ثانیه محقق نشده بود. برای این اصلاح، ادعای تازهٔ هزار کانفیگ در ده دقیقه مطرح نمی‌شود.
